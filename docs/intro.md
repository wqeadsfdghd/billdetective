## 赛事申报版（约 220 字，表单可直接粘贴）

**账单侦探**是一个纯本地的账单分析工具。你把支付宝或微信导出的账单 CSV 拖进来，它会告诉你两件事：钱花在哪了，以及哪些钱正在悄悄流走。

最典型的是订阅：视频会员首月 6 元，第二个月起每月 25 元，扣了半年你才发现。这类「无感扣款」单笔不起眼，年化往往上千。

项目的技术重心不是做图表，而是**把订阅检测做到不误报**。只用「同商户、间隔 30 天」这种规则，会把你每周吃的拉面判成周订阅、把还信用卡判成月订阅——一旦报错，用户就再也不信这个工具。所以检测要过四道关：周期拟合、金额稳定性、消费类别门控、以及主动放弃周付识别。

整个工具零第三方依赖，`python -m billdetective` 开箱即用；报告是单个 HTML 文件，断网可看；也可以打开在线版直接试用，文件不会离开浏览器。

## 完整版（约 750 字，用于发布 / 详细申报）

### 起因

我自己的账单里有一笔每月 25 元的视频会员，扣了七个月我才发现——首月是 6 元的体验价，之后静悄悄恢复了原价。一年三百块，不多，但那种「钱在不被看见的地方流失」的感觉很糟糕。

市面上的记账 App 大多要求授权登录、把账单传到云端，或者花很多精力在做账本分类上。而我只想知道一件事：**哪些钱在定期离开我的账户，我是不是已经不需要它们了。**

于是有了账单侦探。

### 它做什么

导入支付宝或微信导出的账单 CSV（也支持任何含「时间 + 金额」列的表格），输出一份消费体检报告：

- 总支出、总收入、净结余，以及**隐形订阅的年化总额**
- 订阅与固定扣款分组展示，标注扣款周期、已扣次数、年化成本、下次预计扣款日
- 月度趋势、支出构成、花钱最多的商户、单笔最大支出
- 几句自动归纳的结论，例如「检测到 4 项隐形订阅，按年需 ¥912，其中腾讯视频最贵」

报告是一个单文件 HTML，CSS 和图表全部内联，双击就能看、断网也能看、可以直接发给别人——而账单本身始终留在你的电脑上。

### 技术重心：把「不误报」当成第一指标

这类工具最容易翻车的地方不是功能少，而是**乱报**。一个把「每周吃的兰州拉面」判成周订阅的工具，用户点一次就再也不会打开。

所以订阅检测设计了四道关：

1. **周期拟合** — 月 / 季 / 年三档候选周期，必须能解释每一个扣款间隔；允许一次漏扣（间隔可跨 1–3 个周期），但不允许忽长忽短。
2. **金额稳定性** — 订阅价格几乎不变，随手消费不会。用变异系数卡住波动大的商户。
3. **类别门控** — 餐饮、交通、日用、服饰这四类高频习惯消费，除非商户名明确写着「会员 / 订阅 / VIP」，否则不参与判定。
4. **主动放弃周付** — 周级节奏在账单数据里和「习惯性消费」无法区分，宁可不报，也不误报。

另外两类结构性干扰单独处理：**信用卡还款、转入余额宝、提现**属于账户间的资金挪动，计入支出会让整张信用卡的消费被重复计算；**退款成功、交易关闭**的订单直接排除，否则支出虚高。

一个细节：年化按日历月算（月付 × 12），而不是 365/30。差别只有 1.4%，但用户会拿这个数去和自己算的账对比，一旦对不上就失去信任。

### 工程实现

- **零第三方依赖**。全部用 Python 标准库，`git clone` 后 `python -m billdetective` 直接跑，不需要 `pip install` 任何东西。报告里的图表是手写的内联 SVG，所以不引 matplotlib。
- **51 个单元测试**，GitHub Actions 覆盖 Python 3.10–3.13。
- **解析层抗折腾**：支付宝导 GBK、微信导 UTF-8-BOM，两家都在真表头前塞十几行说明文字，列名还随版本变。所以不硬编码行号，而是编码轮询 + 表头自动探测 + 列名模糊匹配。
- **在线版与本地版共用同一套规则**：浏览器版是零安装试用入口，同一份账单在两个版本上必须给出完全相同的数字（示例账单实测：500 条记录 / 491 条有效 / 总支出 ¥40,466.52 / 7 项周期性扣款）。这条约束写进了设计文档，避免双实现走偏。

### 关于原创

从解析、分类到订阅检测的规则和实现，都是从零写的。参考的是公开的记账常识（比如分类关键词），核心的订阅判定逻辑——四道过滤的组合、容忍漏扣的周期拟合方式、隐形与固定账单的区分——是根据真实账单反复调出来的，最初版本曾把沙县小吃和滴滴判成月订阅，那些误判样本直接写进了回归测试。
